# 悟空 M1（AirCat）私有 TCP 协议笔记

> 逆向自设备抓包 + 社区资料（corbamico/phicomm-aircat-srv、hassbian 论坛）。
> 适用于固件仍指向 `aircat.phicomm.com:9000` 的斐讯悟空 M1 空气检测器。

## 基本通信模型

- 传输层：**明文 TCP**，端口 **9000**（固件硬编码域名 `aircat.phicomm.com:9000`）。
- 设备是**客户端**，主动连服务器；连接失败会持续重试（周期约秒级）。
- 设备每约 **3 秒**发一帧数据；服务器对**每一帧**都必须回 ACK，否则设备不会进入正常上报节奏。

## 帧格式

```
+----------------+--------+-----+--------+----------+----------+-----------+
| 固定头 (16 B)   | MAC    | ... | 长度等 | msg_type | JSON 数据 | 帧尾      |
+----------------+--------+-----+--------+----------+----------+-----------+
```

- 固定头（实测样例，16 字节）：`aa ff 01 bc fb d1 39 8f 0b 00 00 00 00 00 00 00`
- 之后是设备 MAC（6 字节）、长度/类型字段等控制字节；
- 数据帧的 JSON 部分是**明文 JSON，所有值都是字符串**：

```json
{ "humidity": "75.96", "temperature": "29.11", "value": "8", "hcho": "10" }
```

| JSON 键 | 含义 | 单位 |
|---------|------|------|
| `temperature` | 温度 | °C |
| `humidity` | 相对湿度 | % |
| `value` | PM2.5 浓度 | µg/m³ |
| `hcho` | 甲醛浓度 | µg/m³ |

- 帧尾标记（6 字节）：`ff 23 45 4e 44 23` = `\xff#END#`
  （`#END#` 前面带一个 `0xff`，**这就是解析时最容易踩的坑**，见 README 踩坑记录第 3 条。）

实测数据帧典型长度 109~110 字节；注册/心跳帧约 34 字节（无 JSON 数据键）。

## ACK 应答

服务器收到任何一帧后，取该帧**前 23 字节**作为应答头，拼接以下固定应答体：

```
\x00\x18\x00\x00\x02{"type":5,"status":1}\xff#END#
```

Python 表示：

```python
END_MARK = b"\xff#END#"
ACK = b'\x00\x18\x00\x00\x02{"type":5,"status":1}' + END_MARK
writer.write(data[:23] + ACK)
```

实测回包长度 55 字节（23 + 32），设备收到后继续按 ~3s 节奏上报。

## 快速验证脚本

`tools/m1_sniff.py` 是一个不依赖 HA 的独立嗅探器：在 HA 主机（或任意能被 DNS 劫持指到的机器）上运行，如果 M1 已被劫持到该机器，就能看到它发来的原始帧，用于确认「设备还认这个域名、还在上报」。
